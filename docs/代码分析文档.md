# SenseVoice ROS2 代码仓库分析与使用文档

> 本仓库是地瓜机器人（D-Robotics / Horizon）出品的一个 ROS2 功能包，将阿里巴巴达摩院开源的 **SenseVoice** 多语言语音识别（ASR）模型集成到 ROS2 中，使机器人能够通过麦克风实时采集语音、检测语音活动（VAD）、进行语音识别，并对外发布识别结果和指令词。

---

## 一、仓库是做什么的

### 定位
`sensevoice_ros2` 是一个面向机器人平台的 **实时语音识别 ROS2 功能包**，核心能力包括：

1. **音频采集**：通过 ALSA（高级 Linux 声音架构）从麦克风设备实时采集 16kHz PCM 音频。
2. **语音活动检测（VAD）**：使用 Silero-VAD 模型判断当前是否有"人在说话"，实现语音端点检测，避免对静音段进行无谓识别。
3. **语音识别（ASR）**：使用 SenseVoice 模型（基于 `ggml` 推理后端，模型文件为 `sense-voice-small-fp16.gguf`）将语音转写为文本。
4. **唤醒与指令词解析**：检测唤醒词（默认"你好"），并在识别文本中匹配配置好的指令词（`config/cmd_word.json`），分别发布 ASR 文本与指令语义。
5. **ROS2 话题输出**：将音频、识别文本、指令词通过标准 ROS2 话题发布，供其他节点订阅消费。

### 适用场景
- 机器人的语音交互入口（"你好，打开灯" → 发布指令词）
- 语音转写 / 字幕
- 多语言（中文、英文等）语音识别前端

## 二、仓库是如何做的（架构与实现）

### 1. 整体架构

```
麦克风 (ALSA plughw)
        │  PCM 音频流 (16kHz, 16bit, 双声道)
        ▼
┌─────────────────────────────┐
│   HBAudioCapture (ROS 节点)  │  src/hb_audio_capture.cpp
│   - 采集线程                 │
│   - 打包 SmartAudioData     │
│   - 发布 /audio_smart       │
└──────────────┬──────────────┘
               │ push_audio_data()
               ▼
┌─────────────────────────────┐
│     speech_engine (单例)     │  src/speech_engine.cpp
│   - VAD (Silero)            │
│   - SenseVoice ASR          │
│   - 生产者/消费者队列        │
│   - 唤醒词 + 指令词匹配      │
└──────────────┬──────────────┘
               │ 回调 AudioASRFunc / AudioCmdDataFunc
               ▼
┌─────────────────────────────┐
│   HBAudioCapture            │
│   - asr_send_th 线程         │
│   - 发布 /asr_text (String) │
│   - 发布 /cmd_word (String) │
└─────────────────────────────┘
```

### 2. 核心模块

#### (1) `HBAudioCapture` — 音频采集 ROS 节点
文件：`src/hb_audio_capture.cpp`、`include/hb_audio_capture.h`

- 继承自 `rclcpp::Node`，节点名可配置（launch 中默认 `hb_audio_capture`）。
- **采集线程** `MicphoneGetThread()`：
  - 通过 `utils/alsa_device.cpp` 封装的 ALSA 接口打开声卡（默认 `plughw:0,0`）。
  - 以 `period_size=512`、`nperiods=4` 为单位循环 `snd_pcm_readi` 读取音频。
  - 将采集到的 sample 打包进 `audio_msg::msg::SmartAudioData` 消息（含声道数、采样率、数据、时间戳等），发布到 `/audio_smart`。
  - 通过 `push_audio_data()` 把音频送入 `speech_engine` 的识别队列。
- **ASR 发送线程** `asr_send_th()`：
  - 阻塞等待 `g_asr_mtx` 条件变量，一旦 `speech_engine` 回调产生识别结果，就把 `g_asr_msg` 发布到 `/asr_text`，把 `g_cmd_data` 发布到 `/cmd_word`。
- 关键参数（可在 launch 中覆盖）：`micphone_name_`、`micphone_rate_(16000)`、`micphone_chn_(2)`、唤醒词 `wakeup_name_`、语言 `language_`、`asr_model_`、`config_path_` 等。

#### (2) `speech_engine` — 语音识别引擎（单例）
文件：`src/speech_engine.cpp`、`include/speech_engine.h`

- **单例模式**（`Instance()` + `std::call_once`），保证全局唯一识别引擎。
- **初始化** `Init()`：
  - 加载 SenseVoice 模型（`sense_voice_init_from_file_with_params`，模型路径由 `TROS_DISTRO` 环境变量拼接 `${TROS_DISTRO}/lib/sensevoice/${asr_model}`）。
  - 初始化 Silero-VAD（`silero_vad_init_from_file`，模型为 `silero_vad.onnx`）。
  - 设置识别参数 `sense_voice_params`（采样率 16000、线程数、语言、VAD 阈值、ITN 逆文本归一化等）。
  - 注册两个回调：`AudioASRFunc`（识别文本）、`AudioCmdDataFunc`（指令词）。
- **生产者/消费者模型**：
  - `send_data()`：生产者，将一帧音频（`vector<double>`）压入 `process_queue`，队列上限 `kMaxQueueSize=10`，满则丢弃并计数。
  - `process()`：消费者线程，循环从队列取数据，调用 VAD 判断语音端点，检测到语音时累积音频，静音超过阈值后送入 SenseVoice 一次性识别。
- **VAD + 识别逻辑**（`SileroVad / vad_process`）：
  - 维护 `triggered` 状态、`vad_data_ptr` 累积缓冲、`speech_pad_ms` 前后padding。
  - 检测到语音开始记录 `vad_start`，静音达到 `min_silence_duration_ms` 判定一句话结束，触发 `sense_voice_full` 推理。
- **识别后处理** `sense_voice_run`：
  - 调用 `sense_voice_full` 得到文本。
  - 若开启 ITN 逆文本归一化，调用 `sense_voice_itn` 将"二零二四"规整为"2024"等。
  - 去掉唤醒词前缀：若文本以 `wakeup_name_` 开头则裁掉，剩余部分作为纯 ASR 文本回调。
  - 指令词匹配：遍历 `cmd_word.json` 中的词表，命中则回调指令词；若全部未命中则回调 "NONE"。

#### (3) `utils/alsa_device` — ALSA 采集封装
文件：`src/utils/alsa_device.cpp`、`include/utils/alsa_device.h`

- 封装 `snd_pcm_*` 系列接口，提供 `alsa_device_init()`、`alsa_device_read()`、`alsa_device_free()`。
- 支持配置声卡名、采样率、声道数、`period_size`、`nperiods`、`buffer_time`。

### 3. 关键数据流

```
麦克风 → ALSA 采集线程(512样本/帧)
        → SmartAudioData 发布 /audio_smart
        → speech_engine::send_data (队列)
        → process 线程 (VAD 累积 → SenseVoice 识别)
        → 回调 AudioASRFunc / AudioCmdDataFunc
        → asr_send_th 线程 → 发布 /asr_text、/cmd_word
```

### 4. 依赖与外部资源
- ROS2（`rclcpp`）、自定义消息包 `audio_msg`（`audio_msg::msg::SmartAudioData`）。
- ALSA 开发库 `libasound`。
- 预编译的 SenseVoice C/C++ 库（`include/sensevoice/` 下的 `.so`、`.a`、`sense-voice.h`、`silero-vad.h`），以及 ONNX Runtime（VAD 推理）。
- 模型文件：`sense-voice-small-fp16.gguf`、`silero_vad.onnx`、`command_executor.toml`、多语言 BPE tokenizer。

## 三、如何使用

### 1. 环境准备
- 运行平台：地平线/地瓜机器人 RDK 系列（依赖 `TROS_DISTRO` 环境变量指定系统发行版，如 `humble`）。
- 已安装 ROS2（humble 等），且安装了 `audio_msg` 自定义消息包。
- 系统已连接并识别麦克风设备（默认 `plughw:0,0`）。
- 模型与 SDK 文件路径需可通过 `TROS_DISTRO` 拼接访问（默认 `${TROS_DISTRO}/lib/sensevoice/...`）。

### 2. 编译
```bash
# 在 ROS2 工作空间的 src 下放置本功能包
cd ~/your_ros2_ws
colcon build --packages-select sensevoice_ros2
source install/setup.bash
```

### 3. 配置
- **指令词**：编辑 `config/cmd_word.json`，配置需要匹配的指令词数组，例如：
  ```json
  {
    "cmd_word": ["打开", "关闭", "前进", "停止"]
  }
  ```
- **Launch 参数**（见 `launch/sensevoice_ros2.launch.py`）：
  - `micphone_name`：麦克风设备名
  - `asr_model`：模型文件名
  - `language`：识别语言（`zh` 等）
  - `wakeup_name`：唤醒词
  - `publish_asr` / `asr_output_mode`：ASR 输出模式
  - `config_path`：配置目录

### 4. 运行
```bash
# 方式一：使用 launch 文件
ros2 launch sensevoice_ros2 sensevoice_ros2.launch.py

# 方式二：直接运行节点（需先 source）
ros2 run sensevoice_ros2 hb_audio_capture
```

### 5. 订阅识别结果
```bash
# 实时查看语音识别文本
ros2 topic echo /asr_text

# 实时查看匹配到的指令词（未命中显示 "NONE"）
ros2 topic echo /cmd_word

# 查看原始音频流（SmartAudioData）
ros2 topic echo /audio_smart
```

### 6. 典型使用流程
1. 说出唤醒词"**你好**"（代码中默认）。
2. 继续说出指令，如"你好，打开灯"。
3. 引擎识别到"你好"前缀后剥离，对剩余文本做 ASR → 发布到 `/asr_text`（如"打开灯"）。
4. 同时与 `cmd_word.json` 匹配的指令词发布到 `/cmd_word`（如"打开"）。
5. 上层业务逻辑节点订阅 `/cmd_word` 与 `/asr_text`，执行对应动作。

### 7. 示例节点（可选）
- `src/audio_example.cpp`：一个订阅 `/audio_smart` 的示例，展示如何接收音频消息并写入文件（`audio.pcm`），可用于二次开发参考。

## 四、总结

| 维度 | 说明 |
|------|------|
| 是什么 | ROS2 实时语音识别功能包，集成 SenseVoice + Silero-VAD |
| 怎么做 | ALSA 采集 → 生产者/消费者队列 → VAD 端点检测 → SenseVoice 推理 → ROS2 话题发布 |
| 输入输出 | 输入：麦克风音频；输出：`/audio_smart`、`/asr_text`、`/cmd_word` |
| 亮点 | 单例引擎、VAD 流式断句、ITN 文本规整、唤醒词剥离、JSON 指令词热配置 |
| 平台依赖 | 地瓜机器人 RDK + ROS2 + ALSA + TROS_DISTRO 模型路径 |

该仓库为机器人语音交互提供了开箱即用的 ASR 前端，开发者只需订阅 `/asr_text` 与 `/cmd_word` 即可快速构建语音控制、语音助手等应用。
